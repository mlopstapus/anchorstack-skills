## Summary

Update `universal/rca/SKILL.md` from v2.0.0 to v3.0.0 to bring it into full compliance with
the anchorstack-skills constitution. Three targeted changes: add security guidance around secrets
exclusion, update frontmatter with explicit input/output declarations, and fix the report template
to use `[ALL_CAPS_IDENTIFIER]` placeholders. Report output path moves from `context/rca-<slug>.md`
to `context/rca/<slug>.md`. Root cause taxonomy gains two categories: process and observability.

## Planned Changes to SKILL.md

### 1. Frontmatter (composability + version bump)

Add `inputs` and `outputs` fields. Bump version to `3.0.0`.

```yaml
---
name: as-rca
version: 3.0.0
tier: universal
inputs:
  - symptom_description: "Natural language description of the broken behavior (required)"
  - project_config: ".claude/anchorstack/project.md (optional — read if present)"
  - evidence: "Logs, stack traces, error messages (optional — use what the user provides)"
outputs:
  - rca_report: "context/rca/YYYY-MM-DD-<slug>.md"
description: >
  Root cause analysis — actively investigates a broken project by reading code, reproducing
  the failure locally, and drilling down the causation chain until the true root cause is
  found. Not a template — an investigation. Use whenever something is broken and the cause
  isn't obvious: errors, crashes, wrong behavior, failing tests, broken deploys, or anything
  where "it worked before and now it doesn't". Trigger on any mention of debugging, something
  broken, an error needing diagnosis, or a fix that keeps not working.
---
```

### 2. Phase 3 — Security note (secrets exclusion)

Add a targeted security note immediately after the instruction to read files:

> **Security**: If you encounter secrets, credentials, API keys, tokens, or other sensitive
> values while reading files — do not include them in the report. Note that sensitive values
> were encountered and omitted if relevant to the investigation.

### 3. Phase 5 — Verification checklist addition

Add a secrets-exclusion check to the existing verification list:

> 4. **The secrets check:** Review what you're about to include in the report. Any secret,
>    credential, or token encountered during investigation MUST be omitted.

### 4. Phase 6 — Report template update

Replace the free-form inline template with a placeholder-driven version using `[ALL_CAPS]`
convention and updated output path:

```markdown
Write to `context/rca/[YYYY-MM-DD]-[SLUG].md`. Create `context/rca/` if it doesn't exist.

[RCA_REPORT_TEMPLATE]
# RCA: [FAILURE_DESCRIPTION]

**Date:** [DATE]
**Status:** [STATUS: Investigating | Root cause identified | Resolved]

## What broke

[WHAT_BROKE]

## Causation chain

[CAUSATION_CHAIN]
  ↓ caused by
**ROOT CAUSE: [ROOT_CAUSE_STATEMENT]**

## Root cause

[ROOT_CAUSE_EXPLANATION]

## Contributing factors

[CONTRIBUTING_FACTORS]

## Fix

[FIX_RECOMMENDATION]

## Prevention

[PREVENTION_RECOMMENDATION]
[/RCA_REPORT_TEMPLATE]
```

### 5. Root cause taxonomy update

Add `process` and `observability` to the category list in Phase 4.
